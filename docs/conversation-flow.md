# 사용자 응답과 다음 상황의 연결

## 표시 순서와 말투

1. 상대방이 사용자의 실제 선택이나 질문에 자연스러운 존댓말 구어체로 답한다.
2. 다음 단계로 이동하면 새 요구·시간 압박·제시 자료를 상대방의 대사에 이어서 소개한다.
3. 그 상황에 대한 대응 질문을 보여준다.

별도의 ‘현재 상황’ 박스는 표시하지 않는다. 내부 분석과 기존 기록 호환을 위한 `kind=situation` 메시지는 저장하되 대화 기록 화면에서는 숨긴다. 따라서 대응 질문에 필요한 전제는 반드시 상대방 대사에도 포함한다.

사용자가 자료를 요청하지 않았는데 ‘요청하신 자료’라고 답하거나, 자료를 확인하지 않았는데 확인을 마쳤다고 취급하지 않는다. ‘말씀이군요’, ‘뜻은 알겠습니다’처럼 사용자 말을 다시 요약하는 상투적인 확인 표현은 줄인다. 여러 단계에서 같은 서두를 반복하지 않는다.

예: ‘오늘 안으로는 힘들 것 같습니다.’

- 상대방: ‘지금 결정하기 어려우시면 잠깐 생각해 보세요. 계약 관련 서류는 지금 바로 보여드리기 어려워요. 우선 계약금부터 진행하시면 어떨까요?’
- 대응 질문: ‘자료가 확인되지 않은 상태에서 계약과 송금을 어떻게 하시겠습니까?’

‘오늘 결정하라는 말’이나 ‘오늘까지만 참여 가능’이라는 질문 앞에는 해당 조건을 상대방 대사에서 명시한다. 투자사기에서 상대방이 제시한 자료를 묻는 단계에도 등록증 이미지와 참여자 사례를 대사로 먼저 소개한다. 상대방의 원금 보장 등은 시나리오 속 인물의 주장으로 유지하며 실제 검증이나 회복을 만들어내지 않는다.

## 질문과 행동 선택

- ‘얼마나 더 여유를 주실 수 있나요?’ 같은 질문만 제출하면 상대방이 시나리오에 맞는 답을 하고 같은 단계에 머문다.
- 질문만으로 채점하지 않으며 완료 단계 수와 재질문 제한 횟수를 늘리지 않는다. 이전에 기록된 행동은 유지한다.
- 행동과 질문을 함께 쓰면 질문에 답하면서 명확한 선택 행동을 반영해 다음 상황으로 진행한다.
- 명확한 통화 종료·거래 철회는 기존 종료 규칙을 우선한다. 명확한 미검증 계약 진행 선택도 위험 행동 지속 결과로 조기 종료한다. 종료 후 상대방이 말을 이어가지 않는다.
- 과거 송금 완료를 서술하면서 질문하면 과거 노출 기록은 보존한다. 이후 안전한 중단으로 바뀌어도 감점을 삭제하지 않는다.
- 의미가 모호한 답변이나 모델·규칙 충돌에는 기존 재질문 처리를 유지한다.

응답 상태 `question_answered`는 일반적인 모호한 응답의 `clarification`과 구분한다. 요청 ID를 재사용하면 같은 응답을 반환하므로 질문이 중복 저장되지 않는다.

## 질문 답변의 범위

행동 추출 프롬프트 `behavior-extraction-v3`는 행동과 별도로 질문 주제를 추출한다. 질문 주제는 시간, 자료, 신원, 금전·정보 요구, 수익·보장, 이유, 기타로 구분한다. 질문 자체를 실행 행동으로 추측하지 않는다.

서버는 주제와 시나리오에 맞는 승인된 답변을 사용한다. 실제 계좌·개인정보, 검증되지 않은 계약 상대 신원, 확정되지 않은 추가 유예 시간 등을 만들어내지 않는다. 주제를 특정하기 어려우면 어느 조건이 궁금한지 구체적으로 묻는다. API를 사용할 수 없는 경우에도 명확한 순수 질문에는 보수적인 질문 판별로 승인된 답변을 제공할 수 있다. 명시적인 행동 선택이 섞인 문장은 이 대체 처리로 덮어쓰지 않는다.

입력 예시도 시나리오별로 다르게 제공한다. 전세사기 화면에 보이스피싱용 ‘전화를 끊고 공식 기관에 확인’ 예시를 공통 표시하지 않는다.

## 검증

구어체 기본 대사·질문 응답·다음 단계 전제 소개 변경 후 서버 자동 테스트 86개가 통과했다. 아래 실제 Gateway 검증은 이전 대화 흐름에 대한 기록이며 이번 문구 변경 후 실제 API 재검증을 의미하지 않는다.

- 백엔드 자동 테스트 77개 통과: 질문 반복 시 단계·점수·재질문 횟수 유지, 요청 재시도, 질문 후 행동 진행, 과거 노출 보존, 상황과 질문 전제 일치 포함
- 프론트엔드 프로덕션 빌드 및 ESLint 통과
- 실제 학교 Gateway로 합성 대화 3개, 13턴 및 총 17회 API 호출 검증 통과
- 전세사기 예상 최종 점수 95점, 보이스피싱·투자사기 각각 100점 확인
- 실제 검증은 임시 로컬 SQLite를 사용하며 운영 DB에 기록하지 않음

재검증 도구는 `backend/check_conversation.py`이며 결과는 로컬 `output/conversation-validation.json`에 저장된다. 이 도구는 직접 실행할 때만 실제 API를 호출한다. 합성 대화 검증은 모든 자유 응답에 대한 정확도 보장이 아니다.

## 대화 이력 기반 응답 생성

단계 전개 시 Gemini는 고정 후보를 고르는 대신 최근 사용자 답변, 전체 대화, 행동 이력, 다음 상황과 대응 질문을 받아 상대방 대사를 작성한다. 단계별 기본 문구는 장애 시 대체 응답으로 사용한다. 사용자에게 없는 자료 요청·검증 행동을 가정하거나 이미 거절한 결정을 다시 묻지 않도록 지시한다. 모델은 점수와 종료 여부를 결정하지 않는다.

명확한 계약·투자 거절은 안전한 중단으로 종료하고, 확인 전 보류 같은 잠정적인 선택은 대화를 이어간다. 생성 응답의 형식·길이를 검사하고 송금 완료 등 근거 없는 결과 표현이나 연락처·URL을 포함하면 기본 대사로 대체한다. 프롬프트와 제한 검사는 모든 자유 생성의 정확성을 보장하지 않는다.

변경 후 자동 테스트 91개 통과. 이번 변경에 대한 실제 Gateway 호출 검증은 별도로 수행하지 않았다.
