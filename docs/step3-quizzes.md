# 3단계: 경제 지식 퀴즈 확장

작성일: 2026-09-28

## 구현 내용

기존 6개 개념의 퀴즈를 각각 1개에서 5개로 늘렸다. 기존 문제 6개를 유지하고 24개를 추가했다. 모든 문제는 고유 ID, 질문, 보기 4개, 정답 인덱스, 해설을 가진다.

| 개념 | 추가 문제의 범위 | 전체 문항 수 |
| --- | --- | --- |
| 금리 | 의미, 단리 계산, 같은 조건의 예금 비교, 적용 금리 변화 | 5 |
| 물가와 인플레이션 | 전반적인 물가, 구매량 계산, 개별 가격과 물가의 구분, 생활비 | 5 |
| 신용점수 | 의미, 납부 일정 관리, 상환 여력, 점수 변화의 불확실성 | 5 |
| 등기부등본 | 소유권·권리관계, 주소 대조, 계약 권한 확인, 문서 확인의 한계 | 5 |
| 안전계좌 | 기관 사칭, 독립적인 확인 경로, 비밀 유지 요구, 소액 송금 | 5 |
| 원금 보장 투자 | 시간 압박, 제시된 사진, 수익 근거와 위험, 후기의 한계 | 5 |

## 출제 흐름

1. 개념 상세 화면에 진입하면 5문제의 순서를 섞고 첫 문제를 보여준다.
2. 보기를 선택하기 전에는 정답 확인 버튼이 비활성화된다. 보기 선택이나 다른 상태 변경으로 문제가 다시 섞이지 않는다.
3. 정답 확인 후 정답 번호·보기·해설을 표시하고 해당 문제의 선택을 잠근다.
4. 다음 문제로 넘어가면 선택과 채점 상태를 초기화한다. 한 바퀴 안에서는 문제 중복이 없다.
5. 마지막 문제 뒤에는 ‘다시 섞어 풀기’를 제공한다. 새 순서의 첫 문제는 직전 마지막 문제와 다르게 한다.
6. 목록으로 돌아갔다가 재진입하거나 다른 개념을 열면 새 순서로 시작한다. 방문 간 중복까지 막지는 않는다.

문제 순서만 섞으며 보기 순서는 바꾸지 않는다. 따라서 정답 인덱스와 해설은 원래 문제에 그대로 연결된다. 학습 결과 저장은 이번 단계에 추가하지 않았다.

## 파일과 API

- `backend/data/learning.py`: 단일 `quiz`를 `quizzes` 배열로 변경했다. 목록·상세 API가 모두 문제 목록을 반환한다.
- `frontend/src/quiz.ts`: 입력 배열을 변경하지 않는 Fisher–Yates 방식의 순서 섞기와 회차 경계 중복 방지.
- `frontend/src/QuizCard.tsx`: 문제 선택·채점·다음 문제·재시작 UI.
- `frontend/src/App.tsx`: 새 데이터 타입과 퀴즈 컴포넌트를 연결하고 개념 변경 시 상태를 초기화한다.

프론트엔드와 백엔드를 함께 최신 코드로 실행해야 한다. 별도 무작위 출제 API나 서버 측 채점은 추가하지 않았으며, 기존 학습용 클라이언트 채점 방식을 유지한다.

## 검증

- 백엔드: `backend`에서 `.venv/Scripts/python.exe -m unittest test_learning test_branching -q` — 24개 통과. 30문항의 수·고유 ID·보기·정답 범위·해설, 목록/상세 API와 기존 시나리오 분기를 확인했다.
- 프론트엔드: `frontend`에서 `node --test tests/quiz.test.mjs` — 3개 통과. 모든 문제가 한 번씩 포함되는지, 원본과 정답 연결이 보존되는지, 회차 경계에서 중복을 피하는지 확인했다.
- `npm run lint`, `npm run build` 통과.
- 브라우저에서의 수동 클릭 시연은 이번 검증에 포함하지 않았다.
